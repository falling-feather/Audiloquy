## 1. 项目简介

`Audiloquy / 语澜` 是一款面向中学英语教师和教研组的本地优先桌面工具。当教师只有试卷、题目框架或文字稿而缺少配套听力资料时，工具帮助其完成：

1. 将结构化文本生成可控的英式或美式英语听力音频；
2. 根据题型框架、答案、难度和时长约束，辅助生成可审阅的听力材料；
3. 将题号与音频语义片段绑定，按题、对话或篇章一键播放和循环；
4. 导出适合教室电脑、广播系统和常见播放器的完整音频及分段音频。

项目的核心不是再做一个通用 TTS 或音乐播放器，而是把“命题/整理文本—审校—合成—编排—课堂播放”连成一个低门槛、可追溯的工作流。

## 2. 宏观背景与机会

- 教师调研已经确认“轻量、便捷、简单可用”是首要需求；高级控制是第二层需求，不能反过来淹没首次使用体验。
- 通用 TTS 擅长把文本变成声音，但通常不理解题号、材料、重复次数、作答停顿和答案证据。
- 音乐播放器可能支持 A-B 循环，却不认识“第 6—7 题对应哪段材料”，也不能在文本修改后自动修正边界。
- 机房或听说考试系统功能完整，但部署、采购和运维通常较重；本项目瞄准教师个人电脑和教研组的小工具形态。
- 北京、广东、上海等地的英语考试形态已经包含机考、听说分离或在线模拟等差异，产品数据模型不能只硬编码一种全国卷顺序。

因此，差异化机会位于四类能力的交集：**考试结构化编辑、可控语音合成、语义分段播放器、简洁/专业双模式**。

## 3. 产品原则

1. **简洁优先**：首次任务应能沿“导入—选择模板—设置口音与 WPM—生成—按题播放/导出”完成，不要求用户理解 SSML、节点或音频术语。
2. **同一工程、双重视图**：简洁模式与专业模式操作同一个底层工程图，不维护两套项目格式；切换模式不丢失高级覆盖项。
3. **本地优先、云端可选**：播放器、工程编辑、缓存和导出不依赖持续联网；云 TTS 和大模型以适配器形式启用。
4. **人审闭环**：模型生成的题目、材料和答案必须经过结构校验与教师确认，不能从提示词直接进入最终播放音频。
5. **可解释与可追溯**：正确答案要能定位到材料证据；每段音频记录声音、模型、语速、文本和生成版本。
6. **兼容真实脏数据**：导入时按内容探测格式，校验试卷、原文、答案和音频的一致性，不信任文件名和扩展名。
7. **面向教室设备**：默认提供单声道兼容导出、响度检查、离线应急和防误操作播放界面。

## 4. 核心能力

### 4.1 简洁模式

- 粘贴文本或导入试卷；
- 选择全国卷、地方卷或自定义模板；
- 选择英音/美音、男女声、目标朗读 WPM；
- 自动安排说明、读题、作答、重复和片尾；
- 一键预听、按题播放、循环和导出；
- 使用自然语言或表单修改，例如“第 8—9 题之间多留 5 秒”。

### 4.2 专业模式

- 结构树、时间线和属性检查器；
- 逐角色声音、发音词典、音素/SSML、语速、停顿、重复、增益和响度控制；
- 精确到采样帧的循环锚点与无爆音边界；
- 查看自动规则与人工覆盖的差异；
- 供应商、模型、缓存、渲染配置和质量诊断；
- 必要时显示节点依赖图，但不把自由节点图作为日常主界面。

### 4.3 听力材料辅助生成

- 给定题目、答案和主题，辅助构造可编辑、可试听的练习材料；生成稿不声称还原遗失的原始听力材料。
- 本地生成优先，教师可主动选择外接服务润色；机器检查结构与事实锚点，语义正确性和答案唯一性仍由教师复核。
- 采用、修改、生成和正式使用分属不同阶段，保留来源与审阅状态；当前输入边界和已实现行为统一见 [开发者文档](01-开发者文档.md)。
- 密钥不进入工程或发行包；离线播放和工程编辑不依赖云服务。

## 5. 大体技术栈

当前已经形成首版 Windows 可执行开发原型；下表同时区分原型实装与产品化建议。

| 领域 | 建议技术 | 在项目中的主要作用 |
| --- | --- | --- |
| 语言与构建 | C++20、CMake | 已实装领域模型、音频编排、校验与 Windows 构建 |
| 桌面界面 | Qt 6 Widgets（已实装）；QML（产品化候选） | 已完成简洁/专业双模式；后续评估时间线交互形态 |
| 语音/播放 | Windows SAPI、独立 Kokoro CLI + WinMM | 已实现本地男女英美语音、缓存与课堂播放 |
| 音频导入/导出 | Windows Media Foundation + PCM WAV 编排 | 已实装常见录音导入、归一化与片段标记；压缩格式导出仍为后续目标 |
| 产品化实时播放 | miniaudio + 平台后端（规划） | 后续低延迟输出、可观测完成状态和设备管理 |
| 变速不变调 | SoundTouch（规划） | 后续独立调整节奏；更高质量方案另行评估许可 |
| 本地数据 | 可移植工程 JSON（已实装）；SQLite（规划） | 工程可复制；后续增加索引、缓存和发音词典 |
| 离线 TTS | Kokoro int8 + 独立 sherpa-onnx CLI | 可一键安装，安装后离线生成；不塞入基础ZIP |
| 在线 TTS/生成 | 供应商适配器 | 云端高质量声音和结构化文本生成，可替换、可禁用 |

总体策略是“**C++ 核心，适度借助成熟库**”，而不是为了纯 C++ 自行重写编解码器、界面框架和推理运行时。

## 6. 项目边界

### 6.1 首个可用版本应包含

- 文本/结构化脚本编辑；
- 多角色 TTS 适配器和局部重生成缓存；
- 目标 WPM、停顿、重复、整场时长编排；
- 题号到材料片段的语义映射与一键循环；
- WAV/MP3 等课堂常用格式导出和基本质量检查；
- 简洁模式主流程与专业模式的必要属性覆盖。

### 6.2 首个可用版本暂不追求

- 无人审核的全自动出题；
- 替代正式考试机构的安全考试平台；
- 首期覆盖所有省份所有历史题型；
- 自研 TTS 基础模型或自研音频编解码器；
- 将公开试卷和听力原文件随安装包再分发。
