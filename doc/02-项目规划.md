## 1. 研究结论摘要

### 1.1 产品结论

1. **方向成立**：教师验证的核心工作不是单纯“文本转语音”，而是用最少步骤得到一套可直接在课堂播放、能按题定位的听力节目。
2. **先做确定性链路**：首期优先实现文本/结构化脚本、TTS、时间编排、语义分段播放器和导出；“依据答案自动生成整套文章”放在其后，因为它的正确性和教研审核成本最高。
3. **双模式必须共用一个内核**：简洁模式是模板/配方视图，专业模式是同一节点图的时间线/属性视图；不能让两种模式产生两份互相漂移的数据。
4. **WPM 不是倍速替代文字**：产品应把目标 WPM 做成可测、可校准的指标，并同时显示篇章节奏与整场时长。
5. **题号循环是核心差异化**：循环对象是稳定的语义片段 ID，而不是手工保存的起止秒数；重新生成某一句后仍然能定位第 6—7 题材料。

### 1.2 技术结论

认可采用 C++，但推荐的是“**C++20 领域/音频内核 + Qt 6/QML 桌面界面 + FFmpeg 格式层 + miniaudio 实时输出 + 可插拔 TTS**”，而不是所有功能从零用 C++ 重写。

这套组合兼顾：

- 对实时线程、内存、缓存、设备和精确时间线的底层控制；
- 对简洁/专业双模式界面的开发效率；
- 对 MP3、AAC/M4A、WAV、FLAC 等真实文件的兼容；
- 将云模型和离线模型与基础安装包解耦；
- 将来跨平台的可能性，同时以 Windows 教室电脑为首要验收平台。

### 1.3 资料结论

初始语料已经覆盖全国卷、省级卷、PDF、DOCX、HTML、MP3、M4A、单声道、双单声道和考试机构官方模拟音频。分析中发现：

- 两套下载音频的链接后缀与真实容器不一致；
- 一份标错卷别的听力原文已被隔离；
- 四套 2024 样本中，持续至少 1 秒的程序性长停顿约占总时长 33%—35%；
- 代表性来源多为单声道或双单声道，支持“教室导出默认 mono”的初步判断。

## 2. 用户、场景与市场空位

### 2.1 核心用户

| 用户 | 主要任务 | 最怕什么 | 产品应提供什么 |
| --- | --- | --- | --- |
| 任课教师 | 临时补齐听力、课堂精听、错题重听 | 配置复杂、反复拖进度条、上课无网 | 五步完成、按题大按钮、离线播放 |
| 备课组/教研组 | 共创材料、统一声音和节奏、审核答案 | 工程不可复现、成员改乱参数 | 模板、审阅状态、工程包、变更说明 |
| 命题教师 | 从框架和答案生成/改写材料 | 答案不唯一、难度失控、音频与题目错配 | 证据链、确定性校验、人审闸门 |
| 信息教师/管理员 | 部署、更新、排障 | 大依赖、密钥散落、设备兼容差 | 便携/静默安装、诊断包、本地优先 |

### 2.2 高频任务路径

**路径 A：已有文字稿**

```text
粘贴/导入文字稿 → 自动识别角色与题组 → 选英/美音和 WPM
→ 局部预听 → 生成整套 → 按题播放或导出
```

**路径 B：只有试卷和答案**

```text
导入试卷 → 解析题型/答案 → 生成结构化草稿
→ 校验正确答案证据与干扰项 → 教师审定 → TTS/编排/导出
```

**路径 C：课堂精听**

```text
打开工程/音频 → 点击“第 6—7 题材料” → 单次/循环/慢速播放
→ 必要时显示原文或逐句播放 → 一键恢复整场模式
```

### 2.3 竞品能力分层

| 类别 | 典型优势 | 对本项目场景的缺口 |
| --- | --- | --- |
| 通用云 TTS | 声音自然、语言和 SSML 能力丰富 | 不理解试题结构；费率参数不等于准确 WPM；联网和成本依赖 |
| 系统内置/离线 TTS | 无网、部署成本低 | 声音选择和自然度不稳定，难以直接形成多角色考试节目 |
| 音频编辑器/播放器 | 波形、剪辑、A-B 循环成熟 | 教师仍需手工找秒数；文字修改后边界会失效 |
| 听说机房/考试系统 | 题库、组卷、录音、考试管理完整 | 采购和部署较重，面向整校考试而非教师日常轻工具 |
| 通用大模型出题 | 起草快、题材多 | 答案唯一性、证据、难度和版权/合规需要额外治理 |

公开采购需求已经表明，完整听说实验室通常包含题库选题、自动组卷、在线音频与录音等成套能力；这反向证明市场空位不是复刻一套机房系统，而是把其中“教师最常用的创作和播放能力”压缩为个人电脑上的轻量工作流。

### 2.4 差异化定位

一句话定位：**面向英语教师的“听力节目 IDE”，简洁模式像表单和播放器，专业模式像可审计的时间线与节点检查器。**

首期不与通用 TTS 比拼声音模型数量，也不与考试平台比拼考务管理；胜负点应是：

- 从试卷到可播音频的时间最短；
- WPM、停顿、重复和总时长可解释；
- 题号定位永远跟随工程结构；
- 无网也能打开、播放、导出和应急；
- 高级用户能检查每个节点而不破坏简洁用户的默认路径。

### 3.3 扩充策略

不要以“下载尽可能多”为目标，而要以“覆盖格式和失败模式”为目标。下一批资料按以下矩阵补齐：

1. **考试形态**：纸笔听力、听说机考、听力与笔试分离、在线模拟；
2. **地区**：全国卷使用地区 + 北京、天津、上海、浙江等独立形态；
3. **文件组合**：试卷+答案+原文+音频四件套、只有试卷/答案、只有网页原文、扫描 PDF；
4. **音频变量**：MP3/AAC/WAV，44.1/48 kHz，mono/stereo，开头结尾静音、不同响度；
5. **结构变量**：单遍/两遍、不同题组、读题时间、口语录音/复述等。

每个新增样本必须经历“来源分级—哈希—文档渲染—音频探测—内容抽检—权利标记”。未经确认的材料只能在隔离区。

这些文件公开可下载且不含个人数据，适合本地产品研发和兼容性评估；但“公开”并不自动等于“可打包再分发”。本轮没有在来源页找到明确的再分发许可。因此：

## 4. 产品信息架构与双模式

### 4.1 共用的工作区

当前开发原型已经采用 `Audiloquy / 语澜` 暖白、靛蓝、青绿视觉令牌，并以“文稿—声音—节奏—生成—课堂”五步导航组织现有编辑、合成和播放器能力；简洁/专业模式仍操作同一个 `Project`。下述三块稳定区域与时间线/检查器仍是产品化目标，不应误写成当前原型已经完整实现。

建议主窗口始终保留三块稳定区域：

```text
┌─────────────────────────────────────────────────────────────┐
│ 工程名  模式切换  保存状态  生成/导出  设备/离线状态          │
├──────────────┬──────────────────────────────┬───────────────┤
│ 题目/材料结构 │ 简洁配方 或 专业时间线        │ 属性/质量检查   │
│ 第1节         │                              │               │
│ 第6—7题材料   │                              │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ 上一题组  播放/暂停  下一题组  循环  速度  音量  当前题号      │
└─────────────────────────────────────────────────────────────┘
```

课堂播放时切换为“大按钮演示模式”，隐藏编辑能力并锁定误触风险；退出演示模式不改变工程。

### 4.2 简洁模式：配方而非时间线

简洁模式只暴露会直接改变教学结果的选择：

- 模板：全国卷/地方模板/自定义；
- 声音：英音/美音、角色 A/B、试听；
- 节奏：目标朗读 WPM、整场预计时长；
- 规则卡片：`每段播放 2 次`、`每题留 5 秒`、`长对话前提示音`；
- 输出：教室兼容、分题文件、整套节目。

“低代码式调整”采用可读规则卡片和自然语言命令，并立即展示会影响哪些节点。例如：

> 第 6—10 题材料播放 2 次；两遍之间停 3 秒；每题作答 5 秒。

系统将其编译为底层节点，用户无需看到节点图。

### 4.3 专业模式：结构树 + 时间线 + 检查器

专业模式提供：

- 逐句/逐角色声音、口音、发音、目标 WPM 与实测 WPM；
- 指令、提示音、停顿、重复、淡入淡出、增益和响度；
- 循环前后安全余量、精确锚点和导出范围；
- 文本证据、正确答案、干扰项说明和审核状态；
- TTS 供应商/模型版本、缓存命中、成本/离线状态和错误诊断；
- 自动规则、模板默认值与人工覆盖项的来源链。

大多数英语听力节目本质上是线性时间线，因此专业主界面不应首先呈现自由节点画布。只有在复用片头、多版本分支、条件输出等场景下，再打开“依赖图”。

### 4.4 模式切换规则

```text
模板默认值 + 简洁模式规则
            ↓ 编译
      规范化节目节点图
            +
      专业模式覆盖项
            ↓
     预览、播放和离线渲染
```

硬性约束：

1. 专业覆盖项以独立 `Override` 保存，不覆盖模板原值；
2. 返回简洁模式时显示“存在 3 项高级覆盖”，而不是丢弃它们；
3. 简洁设置若与覆盖项冲突，先展示影响范围，再允许“保留覆盖/应用到全部/仅新节点”；
4. 播放与导出只消费规范化节点图，避免两套渲染路径产生差异；
5. 工程文件保留 schema 版本和迁移记录。

## 5. 领域模型与工程格式

### 5.1 核心对象

| 对象 | 主要字段 | 职责 |
| --- | --- | --- |
| `ExamProject` | schema、标题、模板、语言、审核状态 | 工程根与可移植保存单元 |
| `Section` | 类型、顺序、规则、题组 | 第一节/第二节等考试结构 |
| `QuestionGroup` | 题号范围、材料 ID、播放规则 | 将多个题绑定到同一材料 |
| `Question` | 题干、选项、答案、证据 | 结构校验和人审对象 |
| `Material` | 标题、说话人、句子、难度目标 | 听力正文的语义容器 |
| `Utterance` | 稳定 ID、角色、文本、声音、发音覆盖 | 最小可缓存 TTS 单元 |
| `CueNode` | 指令、提示音、暂停、重复、标记 | 组成整场节目时间线 |
| `EvidenceSpan` | 材料位置、答案、解释 | 证明答案可从材料得到 |
| `VoiceSpec` | locale、accent、voice、style、rate | 声音意图，不绑定单一供应商 |
| `RenderProfile` | 采样率、声道、格式、响度策略 | 教室/存档/分段输出配置 |
| `AudioAsset` | 来源、哈希、缓存键、时长 | 原始音频和生成片段追踪 |
| `TimeMap` | 语义 ID、起止采样帧、版本 | 播放定位与波形映射 |
| `Override` | 目标 ID、字段、值、来源 | 保存专业模式覆盖且可撤销 |

### 5.2 稳定 ID 与时间映射

- 题目、材料、句子、节点使用稳定 UUID；
- 播放位置使用 `int64` 采样帧，不用浮点秒作为权威值；
- 每次渲染重新产生 `TimeMap`，题号按钮通过语义 ID 查当前时间范围；
- 波形缓存和导出清单都引用内容哈希，避免文字变了而使用旧边界。

### 5.3 保存策略

- **工程 JSON**：用户可复制、审阅、版本控制；保存结构、规则、覆盖和资源引用；
- **SQLite**：保存最近项目、素材索引、语音列表、发音词典、缓存和本机设置；不是工程唯一真值；
- **对象/文件缓存**：TTS 片段以内容寻址目录保存；清理缓存不破坏工程；
- **密钥**：进入 Windows Credential Manager 或等价安全存储，不写工程 JSON、日志或崩溃包。

建议缓存键至少包含：`provider + modelVersion + voice + locale + normalizedText + pronunciation + synthesisOptions + appNormalizerVersion`。

## 6. 技术架构与 C++ 策略

### 6.1 为什么认可 C++

C++ 与本项目的真正匹配点不是“任何语言都比不过它快”，而是：

- 音频回调、无锁缓冲、设备切换、解码和离线渲染需要可预测的资源控制；
- 时间线、波形峰值、长音频流式处理和本地模型推理可共用同一原生内存；
- Windows/WASAPI 和跨平台音频库都有成熟 C/C++ 接口；
- 领域内核可以与 UI、TTS 供应商和文件格式解耦，便于长期维护。

不建议自行开发音频编解码器、GUI 渲染器或神经网络运行时。对一个教师工具，开发速度、崩溃率和部署体验比理论上的最后几个百分点性能更重要。

### 6.2 候选路线比较

| 路线 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| C++ + Qt/QML | 原生内核、成熟桌面 UI、可跨平台、适合时间线 | Qt 体积与许可需治理；QML 需要团队规范 | **推荐** |
| C++ + WinUI 3/C++/WinRT | Windows 集成强、原生风格 | Windows 锁定；复杂自定义时间线开发成本高 | 若明确永远只做 Windows 可复评 |
| C++ + wxWidgets | 相对轻、原生控件 | 高密度现代 UI、动画和时间线效率一般 | 不作为首选 |
| Electron/网页 UI + C++ 服务 | UI 迭代快、生态丰富 | 安装体积和内存更大，双进程边界复杂 | 与“轻量本地工具”目标不优先 |
| Python 全栈桌面 | AI 原型快 | 部署、实时音频和长期工程约束较弱 | 适合一次性研究脚本，不作为产品内核 |
| Rust 内核 | 内存安全、并发模型好 | 团队偏好与桌面/音频整合学习成本 | 非必要迁移，不作为首选 |

### 6.3 建议分层

```text
┌──────────────── Qt/QML Presentation ────────────────┐
│ 简洁工作流 │ 专业时间线 │ 课堂播放器 │ 质量/审核面板 │
└──────────────────────┬─────────────────────────────┘
                       │ C++ ViewModel / Commands
┌──────────────────────▼─────────────────────────────┐
│ Application: 导入、生成作业、撤销、自动保存、导出编排 │
├─────────────────────────────────────────────────────┤
│ Domain: ExamProject、规则编译、节点图、校验、TimeMap  │
├──────────────┬────────────────┬─────────────────────┤
│ TTS adapters │ Audio engine   │ Import/Export       │
│ cloud/offline│ scheduler/DSP  │ PDF/DOCX/audio      │
├──────────────┴────────────────┴─────────────────────┤
│ FFmpeg │ miniaudio/WASAPI │ SoundTouch │ SQLite     │
├─────────────────────────────────────────────────────┤
│ Filesystem / Credential Store / Optional Model Packs│
└─────────────────────────────────────────────────────┘
```

领域层不得依赖 Qt 类型；UI 通过窄接口和不可变快照读取状态。这样可在不启动 GUI 的情况下测试规则编译、时间图、WPM 和渲染。

### 6.4 线程模型

- UI 线程：QML、命令分发、轻量状态更新；
- 后台作业线程：下载、OCR/解析、TTS 请求、缓存和数据库；
- 解码/渲染工作线程：流式解码、重采样、波形峰值、离线输出；
- 实时音频回调：只消费预分配 PCM 环形缓冲，不分配内存、不拿互斥锁、不访问网络/数据库；
- UI 与实时线程之间使用单生产者/单消费者队列传递控制和遥测。

### 6.5 轻量的可验证定义

“轻量”不只看 EXE 大小，按以下顺序验收：

1. 无需服务器即可打开、编辑、播放和导出；
2. 基础安装包不捆绑数百 MB 的离线模型，模型作为独立可选包；
3. 改一句只重新生成和渲染相关片段；
4. 长音频流式解码，波形使用多级峰值瓦片，不把整套 float PCM 常驻内存；
5. 启动快、自动保存、崩溃可恢复；
6. Windows 优先发布，但领域和音频核心保持跨平台边界。

## 7. 音频、WPM 与播放器设计

### 7.1 统一音频图

```text
文件/TTS 片段
  → 内容探测与解码
  → 声道映射
  → 重采样
  → 可选变速不变调
  → 片段增益/响度策略
  → 指令/停顿/重复调度
  → 循环与安全边界
  → 实时输出 或 离线编码
```

预听、课堂播放和离线导出使用同一个调度/处理语义，避免“预听正常、导出错位”。可以有实时和离线执行器，但节点解释必须一致。

### 7.2 为什么 FFmpeg 与 miniaudio 都需要

- miniaudio 适合轻量设备输出、WASAPI 和 PCM 管线，但其内置解码重点是 WAV/MP3/FLAC；
- 真实语料已出现 AAC/M4A，因此仅靠 miniaudio 会在第一批数据上失败；
- FFmpeg 负责广泛格式探测、解码与编码；构建时只启用实际需要且许可兼容的组件；
- Qt Multimedia 可用于平台便利功能，但不作为精确时间线和渲染内核的唯一依赖。

### 7.3 WPM 三层定义

| 指标 | 计算 | 面向用户 |
| --- | --- | --- |
| 朗读 WPM | 规范化后可读词数 / 有声语音分钟 | 简洁模式主速度指标 |
| 篇章 WPM | 可读词数 / 材料首尾时间 | 专业模式与听感校验 |
| 整场节奏 | 说明、材料、停顿、重复、作答和总时长 | 简洁模式预计时长 + 专业结构 |

中国英语能力等级量表给出了慢速 60—80、较慢 80—100、常速 100—140、快速 140—180 WPM 的参考分档。产品可用它做提示区间，但不能直接将某个年级或试卷硬绑定到单一值；真实样本和教师听审仍是最终依据。

### 7.4 准确 WPM 的闭环校准

供应商的 `rate=0.9` 或播放器 `0.9x` 不是准确 WPM。建议流程：

1. 文本规范化：数字、日期、缩写和连字符按实际朗读形式展开；
2. 以英语分词规则统计“可读词数”，保留规则版本；
3. 首次合成后利用时间戳或 VAD/对齐得到有声时长；
4. 计算实测朗读 WPM，与目标比较；
5. 大偏差优先重新请求 TTS 的语速参数，小偏差可在允许范围内用高质量变速微调；
6. 达到容差后保存“目标、实测、调整方式”，未达到则明确告警，不伪造数值。

每个 voice/model 建立校准曲线。专业模式同时显示请求值和实测值；首期目标容差需通过教师盲听后确定，不在本阶段虚构。

### 7.5 题号语义循环

- `QuestionGroup(6-7)` 绑定 `Material(m03)`，材料渲染后产生当前 `TimeMap`；
- “第 6—7 题材料”按钮按语义 ID 查边界，可选是否包含题干/指令；
- 循环有前后安全余量和极短淡化/零交叉处理，避免边界爆音；
- 支持单次、循环 N 次、持续循环、逐句、播完暂停；
- 支持键盘快捷键和课堂大按钮，避免教师回到波形拖动；
- 修改句子后只重建受影响片段及后续时间映射，题号绑定不失效。

### 7.6 导出配置

建议内置：

- **教室兼容**：mono、PCM16 WAV 或高兼容 MP3、保守峰值、完整节目；
- **教研存档**：WAV、可选 stereo、附工程/清单；
- **分题练习**：按材料/题组导出，文件名含题号但不以文件名作内部真值；
- **可编辑交换**：工程 JSON + 引用素材 + 哈希，不必携带可重建缓存。

响度目标在教室实测前保持可配置；引擎按 EBU R128 提供测量和超限提醒，不盲目对所有片段做强压缩。

## 8. TTS 与听力材料生成路径

### 8.1 三层 TTS 策略

| 层级 | 用途 | 优点 | 风险/限制 |
| --- | --- | --- | --- |
| 云端高质量 TTS | 默认高质量生成候选 | 英/美音、多声音、SSML 和时间戳能力较强 | 联网、费用、隐私、供应商变化 |
| 可选离线模型包 | 学校无网、批量生成、可复现 | 本地运行、供应商独立 | 模型数百 MB、CPU 性能、模型/声音许可审查 |
| Windows 已安装声音 | 应急预览与兜底 | 零额外模型、部署简单 | 声音质量和可用 voice 因机器而异 |

基础安装包不含大模型。当前已经实现 `*.voice-pack.json + helper` 的外置协议：应用只负责发现 voice、传递文本/WPM、检查 locale/gender 和复核 PCM 输出；模型运行时隔离在独立进程，因此可在不改主程序 ABI 的情况下替换。清单必须声明运行时与模型许可证，helper 不得越出声音包目录。

离线候选可评估 sherpa-onnx + Kokoro 类模型：官方 C API/预训练模型资料显示其可做离线多说话人 TTS，Kokoro 英语包含美/英男女 voice；但当前官方 Windows 预编译说明不支持 MinGW，且 sherpa-onnx 维护者已公开记录现有 TTS 构建中 `espeak-ng`/`piper-phonemize` 的 GPL 依赖整改计划。因此本轮只交付可插拔协议和假 helper 合约测试，不把该运行时或模型直接塞入基础发行包；待发布模式、依赖树和语音权重许可证逐项签字后再提供安装器。

### 8.2 供应商适配器契约

适配器至少支持：

- 列出 voice、locale、accent、style 和能力；
- 输入规范化文本/SSML、目标声音和速率提示；
- 返回音频、采样率、时间戳、实际模型版本和诊断；
- 可取消、重试、限流、费用预估与离线状态；
- 禁止适配器直接修改工程，只把结果交给应用层事务提交；
- 供应商不可用时，保留已缓存片段并允许切换到另一适配器。

### 8.3 多角色与口音

- `VoiceSpec` 表达“en-GB / en-US、角色特征、性别偏好、风格”，具体 voice ID 是适配器映射；
- 同一对话默认避免两名过于相似的声音；
- 角色口音统一由模板控制，专业模式允许逐角色覆盖；
- 专名、地名、缩写进入工程级发音词典，可试听并锁定；
- 切换供应商时，若无法完全映射，显示差异而不是静默选一个声音。

### 8.4 依据题框和答案生成材料

**当前已实现基线**：对话框接收英文题干、A/B/C、正确答案、主题、A2/B1/B2 与 `50—240` 词目标长度；`LocalScenarioProvider` 默认且离线地处理 `When/Where/Why/What`，生成男女轮次、精确 UTF-8 字节证据、三个选项判断和 `requiresTeacherReview`。教师可主动用 DeepSeek 自然化全部轮次；返回稿必须保持轮次不变量、选项支持/排除角色，并为每项回传包含 canonical option fact 的精确 quote，本地端重算证据位置后复检。界面明确区分“结构与事实锚点通过”和“教师已确认语义唯一性”。采用后文本、请求摘要、证据、provider/model 与审阅状态写入 schema 2；密钥只从环境变量或发布包外私有文件读取。

**产品化目标**：在当前本地基线之外，继续完成试卷解析、模型 JSON 输出、独立批评轮、证据持久化、角色 voice 绑定和导出审计。完整生成链路必须分阶段：

```text
试卷/PDF/DOCX/OCR
  → 题型、题干、选项、答案结构化
  → 生成约束（主题、年级、词汇、时长、口音、答案分布）
  → 大模型输出严格 JSON 草稿
  → 确定性校验
  → 独立批评/修订轮
  → 教师审阅并锁定文本/答案
  → TTS 分句生成
  → 音频/时长/响度/边界 QC
  → 人工试听通过后导出
```

### 8.5 生成结果的必检项

1. 题号连续、选项数量、答案数量和题型规则一致；
2. 每题恰有一个最佳答案，且存在明确 `EvidenceSpan`；
3. 干扰项可从常见误听/推理错误产生，但不能与材料同样成立；
4. 材料不直接机械复述正确选项，除非题型允许；
5. 人物、时间、地点、数值和代词在全文一致；
6. 词数、句长、目标 WPM、材料时长和整场时长处于模板范围；
7. 敏感内容、个人信息、事实陈述和版权来源经过检查；
8. 教师未点击“审核通过”前，工程明显显示“AI 草稿”，禁止批量发布为正式材料。

建议“生成器”和“审查器”使用相互独立的提示/上下文；确定性程序先拦截结构错误，不把所有责任交给第二次大模型调用。

## 9. 质量、合规与非功能目标

### 9.1 目标指标（待原型实测）

以下是拟议验收目标，不代表当前已经达到：

| 维度 | 初步目标 | 备注 |
| --- | --- | --- |
| 冷启动 | 参考 Windows 电脑 ≤ 2 秒进入可操作界面 | 不加载离线模型 |
| 基础安装包 | ≤ 100 MB 为努力目标 | 模型和大素材独立下载 |
| 空工程内存 | ≤ 150 MB 为努力目标 | 需结合 Qt 实测修订 |
| 30 分钟工程 | 不将全量 float PCM 常驻内存；峰值缓存后流畅缩放 | 以流式解码/波形瓦片实现 |
| 局部修改预览 | 缓存命中近即时；新云请求不把网络耗时伪装成内核性能 | UI 显示分阶段耗时 |
| 播放 | 参考设备连续 60 分钟无掉音/爆音 | 同时覆盖设备切换与休眠恢复 |
| 自动保存 | 每个用户命令可恢复，崩溃后提示恢复副本 | 原子替换 + 日志/快照 |
| 离线 | 已有工程、缓存和本地声音可编辑/播放/导出 | 云生成按钮明确不可用原因 |

### 9.2 测试体系

- **领域单元测试**：模板编译、覆盖冲突、题号映射、时间计算、文本规范化、WPM；
- **黄金结构测试**：语料解析结果与固定 JSON 比较；
- **音频不变量**：时长容差、采样率、声道、峰值、响度范围、静音结构、循环边界；
- **格式污染测试**：错扩展名、截断文件、VBR、44.1/48 kHz、mono/dual-mono、HTML 假下载；
- **缓存测试**：文本/voice/模型任一变化只失效正确片段；
- **故障注入**：网络断开、限流、磁盘满、设备拔出、密钥过期、数据库损坏；
- **UI 可用性**：教师在无说明书情况下完成首套生成和按题循环；
- **听审**：英/美音自然度、目标 WPM、停顿、数字/专名发音、教室扩声清晰度；
- **回归策略**：跨 FFmpeg/CPU 不要求逐样本 PCM 完全一致，比较结构、容差和感知哈希。

### 9.3 AI 生成内容标识

《人工智能生成合成内容标识办法》自 2025-09-01 起施行，并覆盖音频等生成合成内容。产品架构应预留：

- 编辑器和审核页的显著“AI 生成/合成”状态；
- 导出文件元数据中的生成来源、模型/voice、时间、工程 ID 和内容哈希；
- 依据实际服务场景决定显式标识的呈现方式；
- 不提供“静默移除依法应保留标识”的功能；
- 发布前由专业人员按产品部署方式确认适用义务。

### 9.4 隐私与安全

- 默认不上传整份试卷，云 TTS 只发送当前需要合成的文本片段；
- 大模型解析/生成前显示将发送的内容和供应商；
- 本地工程、缓存和日志允许一键清理；
- 日志默认记录哈希和错误码，不记录完整密钥或不必要的全文；
- 学校代理、证书、离线策略和数据保留期进入管理员配置；
- 默认不开启遥测，若未来启用必须明确选择并可撤回。

### 9.5 第三方许可门禁

| 组件 | 当前判断 | 进入产品前的门禁 |
| --- | --- | --- |
| Qt 6 | 开源版本涉及 LGPLv3/GPLv3，另有商业许可 | 确定闭源/开源模式、动态链接和模块清单；必要时采购商业许可 |
| FFmpeg | 默认可按 LGPL 配置，启用特定组件可能转为 GPL | 固定 configure 清单、生成 license report、禁止未审计组件 |
| SoundTouch | LGPL 2.1，另有商业许可路径 | 确认动态链接/再分发义务和质量是否满足 |
| Rubber Band | GPL 或商业许可 | 仅在开源兼容或购买许可后采用 |
| SQLite | 官方声明为 public domain | 保留来源与版本/SBOM，仍做安全更新 |
| sherpa-onnx / ONNX Runtime | 上游分别为 Apache-2.0 / MIT | 模型权重、voice、算子和捆绑方式逐项审计 |

许可判断必须落到实际构建产物和 SBOM，不能只看项目首页；本表不是法律意见。

## 12. 需负责人决策

以下四项会显著改变工程和许可，不应由架构文档代替负责人决定：

1. **平台**：Windows 优先、保留跨平台（推荐）还是明确 Windows-only；
2. **发布模式**：闭源商业、开源，或核心开源/服务商业；这决定 Qt、FFmpeg 和变速库的组合；
3. **首选 TTS**：云端高质量为默认、离线为可选（推荐），还是必须从第一版完全离线；
4. **模型生成范围**：在当前 `When/Where/Why/What` 本地确定性基线之外，何时接入大模型、整套试卷解析和证据持久化。

正式项目名称已确认为 `Audiloquy / 语澜`。仍需确认种子学校/教师数量、可接受基础安装包大小、目标最低 Windows 版本和是否允许联网。

| 自动生成答案不唯一 | 高/高 | 当前机器只执行结构、事实锚点和声明关系校验；界面不再冒称语义唯一，必须由教师显式确认 | 教研测试集与独立语义验证达到明确门槛 |
| 声音供应商变化/断网 | 高/中 | 适配器、缓存、Windows/离线兜底 | 故障注入与切换测试通过 |
| Qt/FFmpeg/模型许可不匹配发布模式 | 中/高 | 构建级 SBOM、最小组件、发布前法律审查 | 发布模式确认并完成审计 |
| “准确 WPM”被供应商 rate 参数误导 | 高/高 | 合成后测量与闭环校准 | 教师盲听确定容差和基准 |
| 教室扩声设备差异 | 高/中 | mono 默认、保守响度、多设备试点 | 三类真实设备测试通过 |
| 公开试卷被误当可再分发素材 | 中/高 | 原文件排除 Git/安装包；自制演示集 | 获得明确授权或使用自制内容 |
| 专业模式拖累简洁体验 | 中/高 | 同源图、渐进披露、默认隐藏高级项 | 用户走查证明核心路径无干扰 |
| 离线模型使安装包过大 | 高/中 | 独立模型包、按需安装 | 定义模型包选择与磁盘预算 |

当前暂缓：

- 自研基础 TTS 模型；
- 完整考务、学生账号、在线监考和成绩系统；
- 自由节点画布作为主编辑方式；
- 未经许可的高考试卷/音频随产品分发；
- 在首个音频原型前建设大规模云后端。
