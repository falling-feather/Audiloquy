## 0. 当前基线与硬规则

**当前基线**：开发原型（未编号）。已经形成可运行的 Windows 桌面程序，采用 `Audiloquy / 语澜` 品牌、项目内无边框窗口壳与“文稿—声音—节奏—生成—课堂”五步界面，贯通本地优先/可选 DeepSeek 情景草稿、题组编辑、系统与外置 voice 审计、逐轮男女声合成、目标 WPM、分段/整套 WAV、生成后自动预览、暂停/定位/循环、schema 2 工程保存和简洁/专业视图。

**本轮交付**：[独立备课第一轮：UI-003、AUDIO-005、DATA-003](03-开发历史.md#21-独立备课第一轮)。未来目标见 [项目规划](02-项目规划.md)。

**硬规则**：

1. `listening::Project` 是工程权威状态；Qt 控件、生成缓存和 WAV 时间只由它派生。
2. 题组通过稳定 `Segment::id` 查找；题号和文字变化不得替代稳定 ID。
3. 当前系统 TTS 固定输出 PCM16、mono、44100 Hz；WAV 拼接器拒绝格式不一致的片段。
4. SAPI 的 rate 只是目标 WPM 的近似映射，界面不得把它描述为实测 WPM。
5. `build/`、`dist/`、`prototype-output/` 和 `tmp/` 是生成物；源码真值只在 `src/`、`tests/`、`examples/`、`scripts/` 和根 CMake 配置。
6. 本地已初始化 Git，正式产品版本号仍待分配；首次源码同步遵循用户直接发布授权，使用未编号提交，不把此前工作区迭代伪装成旧 Git 提交。
7. 未保存工程不得隐式写入用户 Documents；默认输出必须由 `defaultOutputDirectory` 解析到当前工作目录下的 `ListeningStudioResults/<project-id>/`。
8. 情景生成草稿必须通过 `validateScenarioDraft`；该函数只证明结构、证据定位与声明的支持/排除关系一致，不得描述为已经证明自然语言语义唯一。
9. schema 2 工程持久化精确男女 voice token、回退规则、生成题干/选项/答案、证据、provider/model、教师审阅状态及最近 WAV 路径；schema 1 读取后在内存迁移为 schema 2。
10. 合成前必须把 `MAN:`/`WOMAN:` 行拆成独立轮次并去掉标签；男、女轮次按实际已安装 locale/gender voice 分别合成，再插入 280 ms 轮间静音。严格匹配失败必须阻止或由用户显式允许性别回退，不得静默冒充目标口音/性别。
11. 情景生成默认只运行 `LocalScenarioProvider`。DeepSeek 只能由教师主动选择；请求会包含题干、选项、答案、主题和完整本地稿。它可自然化全部轮次，但必须保留 ID/顺序/角色/数量，并为每个选项回传包含 canonical option fact 的精确证据锚点，随后再次通过 `validateScenarioDraft`。
12. API 密钥仅允许从 `DEEPSEEK_API_KEY`、`%LOCALAPPDATA%/Audiloquy/deepseek.txt` 或 `.private/deepseek.txt` 读取；不得写入源码、日志、工程 JSON、`dist/` 或 ZIP。
13. 基础发行包不捆绑许可尚未核清的神经 TTS 运行时或模型；外置声音包 helper 必须位于声音包目录内、声明运行时/模型许可证，并输出经重新检查的 PCM16 mono 44.1 kHz WAV。
14. `RenderJobController` 的工作线程只使用快照，结果回到 UI 线程后应用；不得从后台访问控件或活跃工程。取消不删除已完成产物。
15. 所有工程写入统一经过原子保存，草稿用途不放宽结构约束。恢复记录和目录包由各自存储服务管理，不复制用户私有配置。

## 1. 系统定位与已实现范围

当前原型用于验证“题框生成/文本编辑 → 本地英语语音 → 节目编排 → 按题组播放/循环”的纵向链路。

### 1.1 已实现

- `Audiloquy / 语澜` 暖白、靛蓝、青绿视觉体系和五步工作流导航；
- Qt Widgets 三栏工作台、底部播放条和可拖动/缩放/最大化的项目内无边框窗口壳；
- 简洁编辑与专业检查视图共用同一工程；
- 情景生成对话框输入英文题干、A/B/C、正确答案、主题、A2/B1/B2 难度和 `50—240` 词目标长度；
- 本地确定性生成 `When/Where/Why/What` 男女轮次、精确 UTF-8 字节证据、干扰项判断和教师复核标志，并可采用到当前题组；教师可选用 DeepSeek 自然化全部轮次并重建事实锚点，失败自动保留本地稿；
- 空白工程、三题组自制示例、外部 JSON 打开/保存；题组新增、复制、删除、拖动或按钮排序、结构操作撤销与重做；
- 题号范围、角色、英文台词、停顿、重复次数编辑；
- 枚举 SAPI 与项目外置声音包的 locale、性别和 token，分别选择/试听男声与女声，并支持严格口音和显式性别回退；
- 独立后台任务按工程快照生成音频，SAPI 与外置 helper 可取消；按实际音色和文稿复用语音缓存，节奏变化只重新编排；
- 单题组 WAV 与整套节目 WAV 生成，点击生成后立即自动播放预览；
- 选中题组播放、暂停/继续、进度显示、拖动定位、持续循环、停止、上一组/下一组和整套播放；
- schema 2 保存 voice、生成证据/来源/教师审阅和音频引用，schema 1 自动迁移；草稿可原子保存、异常退出后恢复，工程与 WAV 可打包带走；
- 稳定 ID、Unicode JSON、WPM/时长估算与输入校验；
- 可携带 Windows 文件夹和 ZIP 打包；
- 应用/任务栏/文件图标、统一项目内提示框，以及模块回归和真实 GUI 冒烟；测试清单以 [CMakeLists.txt](../CMakeLists.txt) 为准。

### 1.2 尚未实现

- 从 PDF/DOCX/OCR 自动提取试卷；
- 通用云端/本地大模型适配器；当前只实现 DeepSeek 可选润色器，不能改变题目事实或负责最终语义审定；
- 准确实测 WPM 校准、词级时间戳和波形时间线；
- MP3/AAC/M4A 导入、FFmpeg 导出、响度归一化；
- 完整编辑命令历史、跨设备自动同步、全局缓存清理管理和压缩工程格式；当前提供题组结构撤销、独立恢复草稿和目录包；
- 安装器、自动更新、云 TTS、官方签名/自动安装的神经 TTS 模型包与完整 AI 内容标识。

## 2. 总体架构

```text
Qt Widgets MainWindow ── 编辑命令 ── Project / Segment + 结构历史
       │                                  ├─ 原子 JSON / 会话恢复草稿
       │                                  ├─ 相对资源解析 / 打包目录
       │                                  └─ 本地情景 / 可选 DeepSeek + 证据复核
       │ 不可变工程及声音包快照
       ▼
RenderJobController ── 工作线程 ── 角色拆分 / 实际 voice / 语音缓存
       ▲                                  ├─ SAPI（可取消）
       │ UI 线程进度与结果                  └─ 外置 helper（可取消）
       │                                          ▼
       └────────────────────────── PCM WAV 编排 / 原子发布
       │
       └─ 完整题组 / 整套音频 ── waveOut 播放 / 暂停 / 定位 / 循环
```

领域模型和校验不依赖 Qt；原子保存与恢复服务使用文件系统及平台文件/进程接口，`listening_storage` 单独连接领域与音频校验库。平台层不修改工程。`ScenarioDialog` 先生成并校验本地草稿，教师主动选择时才调用 DeepSeek；采用后写入 `Segment`。后台生成只返回完整产物，由 UI 更新工程并调用 `waveOut` 播放。具体接口以 [render_job.h](../src/app/render_job.h)、[project_storage.h](../src/core/project_storage.h)、[recovery_store.h](../src/core/recovery_store.h) 为准。

## 5. 启动与运行流程

1. `main.cpp` 建立 `QApplication`，设置 Fusion 风格、Segoe UI、Qt 资源图标和 Windows 应用图标。
2. `MainWindow` 以 `Qt::FramelessWindowHint` 构建项目内标题栏、题组导航、文稿工作区、声音检查器和课堂播放条；`nativeEvent` 负责 Windows 边缘缩放与标题区拖动。
3. 点击“智能生成情景”后，`ScenarioDialog` 收集题干、三个选项、正确答案、主题、难度和目标词数；本地 provider 始终先生成并复核草稿。
4. 教师可直接采用本地稿，或主动选择 DeepSeek 润色。后者可改写全部轮次，但每个选项/角色关系必须回传精确 quote 且保留 canonical option fact；应用重算 UTF-8 byte offset，再运行 `validateScenarioDraft`。失败不覆盖本地稿。
5. 对话框展示结构化男女轮次、精确证据、三个选项判断和来源链；只有点击“采用到当前题组”才把 `renderDialogueScript` 与 `GenerationRecord` 写入 `Segment`，同时使旧 WAV 缓存失效。专业模式允许教师明确确认语义唯一性。
6. 其他 UI 修改同样实时写回 `Project`；影响音频的修改会清除对应 WAV 映射和整套输出引用。
7. 保存使用显式 `ValidationPurpose::Draft`，允许空标题与未填写正文，但不放宽 ID、编码、数值和结构校验；生成保持严格校验，单组选中生成不受其他空稿组阻碍。
8. `defaultOutputDirectory` 根据工程是否已保存选择 JSON 邻接目录或当前工作目录下的 `ListeningStudioResults`，调用方再创建目录。
9. `RenderJobController` 接收项目和声音包快照，工作线程用唯一的 `parseSpeechTurns` 拆分角色、核验实际音色并合成；轮次之间插入 280 ms 静音。后台不读取控件。
10. `buildProgramWav` 在每一遍后插入停顿，按整采样帧计算静音，分块写入并响应取消；只在完整写入后原子发布。题组与整套文件名包含编排指纹，旧有效文件不被半成品覆盖。
11. 控制器在 UI 线程发出进度及结果；完成结果回写工程，成功时自动试听。取消或失败也保留已完整完成的题组，整套只在全部成功时发布。播放器仍使用 `waveOut` 和 120 ms UI 状态轮询。
12. 编辑草稿定时写到独立会话目录；正常保存或明确放弃时清理。关闭时先结束后台任务，再处理未保存更改，最后关闭音频设备。

## 6. 核心模块与接口

### 6.1 领域核心

| 接口 | 输入 | 输出/副作用 | 失败行为 |
| --- | --- | --- | --- |
| `validate(Project)` | 工程快照 | `ValidationIssue` 列表 | 不抛异常 |
| `requireValid(Project)` | 工程快照 | 无 | 抛出 `ValidationError` |
| `countReadableWords(text)` | UTF-8 英文 | 稳定词数 | 非法字节按分隔符处理 |
| `estimateReadingDuration` | 文本、目标 WPM | 毫秒 | 非法 WPM 抛异常 |
| `estimateProjectDuration` | 工程 | 含重复/停顿的预计时长 | 工程非法或溢出时抛异常 |
| `Project::findSegment(id)` | 稳定 ID | 可空指针 | 找不到返回 `nullptr` |
| `saveProject/loadProject` | `Project`/路径、显式校验用途 | 原子保存 UTF-8 JSON/读取工程，默认严格校验 | I/O、格式或验证错误抛 `ProjectFormatError` |
| `defaultOutputDirectory` | 工程 JSON 路径、当前工作目录、工程 ID | 纯路径计算，不访问文件系统 | 空工作目录、非法 ID 或不可用保存路径抛 `OutputPathError` |

### 6.2 情景文稿生成

| 接口 | 输入 | 输出/副作用 | 失败行为 |
| --- | --- | --- | --- |
| `classifyQuestion` | 英文题干 | `When/Where/Why/What/Unsupported` | 不抛异常 |
| `validateScenarioRequest` | `ScenarioRequest` | 结构、UTF-8、重复选项、答案和词数问题列表 | 不抛异常 |
| `ITextGenerationProvider::generate` | 已组装请求 | provider 中立的 `ScenarioDraft` | provider 自行报告失败；调用方仍必须复核草稿 |
| `generateLocalScenario` | 四类受支持题干与约束 | 确定性男女轮次、证据、判断、词数和人审标志 | 请求或草稿非法时抛 `ScenarioValidationError` |
| `validateScenarioDraft` | 原请求、候选草稿 | 校验来源一致、轮次、UTF-8 字节证据、声明的唯一支持关系和元数据；不证明开放语义唯一 | 不抛异常 |
| `renderDialogueScript` | 已校验草稿 | 每轮一行的 `MAN:`/`WOMAN:` UTF-8 文本 | 草稿非法时拒绝渲染 |
| `DeepSeekScenarioPolisher` | 已校验本地稿、私有密钥 | 自然化全部轮次、重建事实锚点并返回模型/token 元数据 | 缺密钥、网络、HTTP、JSON、不变量、canonical fact 或复核失败时返回错误，本地稿保持不变 |

`LocalScenarioProvider` 是默认且唯一负责建立正确答案、证据角色和选项判断的 provider。`DeepSeekScenarioPolisher` 位于 Qt 应用层，只接受已经校验的本地稿；它可重写证据句周边措辞，但不能改变选项/支持角色，且证据 quote 必须逐字出现在返回轮次并含原选项事实。无论是否润色，采用前都必须运行 `validateScenarioDraft`，随后仍由教师确认自然语言语义。

本地模板会把英文主题的前六个词写入对话开场；A2/B1/B2 会选择简易、标准或进阶的开场表达，因此两个控件会真实改变可听正文。它们仍是有限规则，不等同于完整 CEFR 词汇与句法分级；对话框用工具提示明确这一点，全文仍需教师复核。

### 6.3 Windows 语音与播放

| 接口 | 职责 | 关键约束 |
| --- | --- | --- |
| `listVoices` | 列出 SAPI voice 的 token、名称、locale 与 gender | 所有文本在边界转换为 UTF-8 |
| `chooseBestVoice` | 纯函数按 token、locale、gender 和严格条件打分 | 严格条件不满足时返回空；不会伪装目标能力 |
| `selectVoice` | 对 SAPI 枚举结果执行实际选择 | 选声/回退由 `VoiceSelectionOutcome` 显式报告 |
| `approximateSapiRateForWpm` | 将 WPM 映射到 SAPI `[-10,10]` | 近似值，不是实测 WPM |
| `synthesizeToPcmWav` | 以选定 token/locale/gender 原子生成 PCM WAV | 固定 44100 Hz、mono、16 bit；结果报告实际 voice |
| `WavPlayer::playAsync` | 解析 WAV、载入 PCM 并开始播放 | 不把文件路径交给旧式字符串播放器，中文路径可用 |
| `WavPlayer::snapshot/pause/resume/seek` | 查询进度与状态、暂停/继续、毫秒定位、循环续播 | 同一实例串行访问 `waveOut`；UI 周期轮询 snapshot |
| `WavPlayer::stop` | reset、unprepare 并关闭当前设备 | 关闭/切换前调用 |
| `LocalVoicePackManager` | 发现清单、枚举 voice、调用 helper 并校验 WAV | helper 必须位于包目录内；许可字段、locale/gender、退出码和 PCM 合约均需通过 |

### 6.4 WAV 编排

`buildProgramWav` 接受 `ProgramClip` 数组和可选取消回调。每遍播放后都插入静音（包括最后一遍），静音先计算采样帧数再换算字节，避免半帧。重复和停顿超限明确失败，不静默截断；长静音重复使用零缓冲区，语音数据按块前进。只支持未压缩 PCM，输出受 RIFF 4 GiB 限制。

## 7. 数据、缓存与输出

### 7.1 工程 JSON

`Project` 当前 schema 为 2；读取 schema 1 时补齐安全默认值并在内存迁移。字段包含：

- `id`、`title`、`accent`、`targetWpm`、`voiceSettings`、`renderedProgramFile`；
- `segments[]`；
- 每段的 `id`、`questionStart`、`questionEnd`、`speaker`、`text`、`pauseAfterSeconds`、`repeatCount`、`renderedAudioFile`；
- 可空 `generation`：provider、model、题干、A/B/C、答案、证据、`requiresTeacherReview` 与 `teacherReviewed`。

JSON 是工程真值；WAV 路径只是可失效引用。相对路径以工程目录解析，旧绝对路径继续可读；另存为先按旧位置解析再重定位。重开会报告缺失或无效的音频；文字、音色、WPM、停顿或重复变化使相应成品引用失效，独立语音缓存仍可复用。草稿持久化使用显式校验用途，默认严格 API 语义保持不变。

### 7.2 输出位置

- 已保存工程：在工程文件旁建立 `<工程文件名>_audio/`；
- 未保存工程：在程序当前工作目录下建立 `ListeningStudioResults/<project-id>/`；`scripts/run-prototype.ps1` 从项目根启动，因此脚本运行时结果位于项目根的 `ListeningStudioResults/`；
- `.cache/voice/`：基于正文、实际音色、WPM、规则和声音包配置指纹的语音及单遍组合缓存；
- 题组和整套 WAV 使用不可变的编排指纹文件名；具体命名由 [render_job.cpp](../src/app/render_job.cpp) 定义，不把可含冒号的稳定 ID 直接用于 Windows 文件名；
- “打包带走”生成新目录，包含 `project.json` 与 `audio/` 下相对引用的完整音频，不复制缓存、声音包或密钥。

语音与编排分别缓存，修改停顿、重复或题号不改变语音 key。缓存 WAV 会复核 PCM 合约；旧版本文件暂不自动清理，便于撤销恢复。目录包可整体搬移后打开；换电脑播放不要求重装音色，重新生成需要可用声音。

### 7.3 情景草稿与证据状态

`ScenarioDraft` 在情景对话框内包含原始 `ScenarioRequest`、题型、男女 `DialogueTurn`、按 UTF-8 字节定位的 `ScenarioEvidence`、三个 `OptionJudgment`、词数和 `requiresTeacherReview`。教师采用后，渲染文本与压缩后的 `GenerationRecord` 一起进入当前 `Segment`；专业模式可标记教师确认，保存后可恢复。手工修改正文会主动废弃旧生成审阅记录，避免证据与新文稿错配。

DeepSeek 的 provider 与模型名进入 `GenerationRecord`，token 统计仍只存在于对话框会话。密钥解析顺序为：`DEEPSEEK_API_KEY`、`%LOCALAPPDATA%/Audiloquy/deepseek.txt`、当前工作目录 `.private/deepseek.txt`、程序目录 `.private/deepseek.txt`。读取值不进入状态文案或错误日志；`.private/` 已加入忽略规则且不会复制到发布包。

## 10. 修改与扩展指南

### 10.1 新增工程字段

1. 修改 `src/core/project.h`；
2. 在 `validate` 增加边界；
3. 同步 `toJson/fromJson`；
4. 扩充 `tests/core_tests.cpp` 往返与非法输入；
5. 在 `MainWindow` 加载、提交和失效缓存；
6. 运行全部 CTest，并决定 schema 是否需要升级。

禁止只改 UI 控件而不写入 `Project`，也禁止只改 JSON 而不更新校验。

### 10.2 新增 TTS 供应商

先从 `windows_audio.h` 抽取平台无关请求/结果接口，在应用层选择 adapter。供应商必须返回实际 voice/model、音频格式、时长和回退信息；不得直接修改 `Project`。新输出必须先经过 PCM/格式规范化，才能进入 `buildProgramWav`。

### 10.3 增加题组 UI

新增、删除、排序必须操作 `Project::segments` 并生成不重复稳定 ID；删除时同步清理 `segmentWavs_`，排序后重新生成整套节目。测试至少覆盖重复 ID、空工程和选中项删除。

### 10.4 增加情景生成 provider

1. 在 `src/core/` 实现 `ITextGenerationProvider::generate`，不得依赖 Qt 控件或直接改写 `Project`；
2. provider 返回完整 `ScenarioDraft`，证据偏移必须按 UTF-8 字节计算并精确对应 `DialogueTurn::text`；
3. 在应用层明确选择 provider，并在采用前调用 `validateScenarioDraft(sourceRequest, draft)`；
4. 失败只更新对话框错误状态，不得污染当前题组；教师采用后再统一清理题组 WAV 和整套 WAV 引用；
5. 为新 provider 增加合法、歧义、缺字段、错误证据、错误答案和边界词数测试，并运行全部 CTest。

当前 DeepSeek 实现比通用 provider 更窄：它只做本地稿自然化，不负责建立正确答案或最终语义审定。修改 `deepseek_scenario_polisher.*` 时必须保留 option/role 关系、canonical fact、精确 quote、ID/角色/顺序/数量不变量、35 秒超时、无响应正文日志和失败不覆盖本地稿。

## 11. 已知限制与故障排查

| 表现 | 原因 | 当前处理 |
| --- | --- | --- |
| 选择英音后不能生成 | Windows 未安装 en-GB voice，严格口音按设计阻止冒充 | 在 Windows 安装真实 en-GB voice 后重启；不要用性别回退绕过 locale |
| 男声或女声不可选/不能生成 | 对应 locale+gender 的 SAPI 或外置声音包 voice 未安装 | 安装对应系统 voice，或在声音包目录放入已核验清单后“重新扫描”；应急时可显式允许性别回退 |
| 声音仍显机械 | 当前选中的是 Windows SAPI 系统 voice，无法保证神经音色或真人自然度 | 先试听并由教师听审；可接入自行完成许可证与听审的 helper 声音包，基础包不预装模型 |
| 显示 120 WPM 但听感略有偏差 | SAPI rate 是近似映射 | 原型限制；后续合成后测量校准 |
| 生成期间不能编辑文稿 | 当前任务使用固定快照 | 等待结束或取消，保留已完成题组；不需要结束进程 |
| 修改后旧 WAV 仍在磁盘 | 版本化成品供撤销引用，语音缓存供复用 | 确认不用的工程输出可由用户清理；尚无自动缓存清理管理 |
| 未保存工程的输出位置不明确 | 输出相对程序启动时的当前工作目录 | 点击“打开输出文件夹”；脚本启动时固定为项目根，直接运行便携 EXE 时通常为 EXE 所在目录 |
| 自动恢复不可用 | 恢复目录不可写或记录损坏 | 查看状态提示并手动保存；恢复草稿不会自动覆盖原工程 |
| 搬运后音频缺失 | 只复制了 JSON，或复制时漏了 audio 目录 | 使用“打包带走”并复制完整目录，再打开其中的 project.json |
| 当前机器的男女情景只能回退为同一声音 | 测试机只有 Microsoft Zira Desktop（en-US，Female），不存在真实男声 token | 默认严格模式会阻止；只有用户主动允许性别回退才生成，并在状态中标记实际 voice |
| 旧 schema 1 工程没有生成证据 | 旧文件从未保存这类字段 | 打开后自动迁移为 schema 2；新采用的草稿会保存证据与审阅状态，旧内容不能凭空还原 |
| 题干不是 When/Where/Why/What 时无法生成 | 本地确定性 provider 只实现四类锚定模板 | 手工编辑，或后续接入仍受结构校验约束的模型 provider |
| DeepSeek 按钮提示未配置 | 私有密钥没有出现在允许的读取位置 | 设置 `DEEPSEEK_API_KEY` 或写入 `%LOCALAPPDATA%/Audiloquy/deepseek.txt`；不要把密钥放进 `dist/` |
| DeepSeek 失败后仍显示本地稿 | 网络/HTTP/JSON/不变量或证据复核失败 | 这是本地优先的保护行为；查看不含密钥和响应正文的错误摘要后重试或直接采用本地稿 |
| 不能导入 MP3/M4A | 尚未接 FFmpeg | 当前只生成/播放 PCM WAV |
| 外置声音包未出现 | 清单字段不完整、helper 越出包目录、文件缺失或 locale/gender 非法 | 检查 `%LOCALAPPDATA%/Audiloquy/voice-packs` 和 `voice-packs/README.txt`，修正后点击“重新扫描音色” |
| 打包程序缺 DLL | 旧打包目录未经过依赖递归复制 | 重新运行 `build-prototype.ps1`，不要只复制 EXE |

## 13. 独立备课实现说明

2026-09-08 第一轮实现与验收，任务索引及验证见 [开发历史](03-开发历史.md#21-独立备课第一轮)。

当前可从空白编辑、取消后台生成、安全保存与恢复、携带完整工程和音频。以下解释跨模块业务边界；具体字段以对应源文件为准。

- **编辑边界**：新题组使用新的稳定 ID；复制不复用 ID 和音频引用，保留题目信息但恢复待审阅状态；排序保留题号。结构撤销与重做保留存活题组的后续正文修改，并清除可能过期的整套引用；跨声音设置恢复的历史题组需重新生成。结构历史和原生文本编辑撤销不等同于完整工程命令栈。
- **存储边界**：空白文稿属于可保存草稿，渲染仍要求完整内容；非法 ID、编码、数值和结构不能通过草稿通道绕过。先完整写临时文件，再原子替换目标文件；不得把自动恢复当成原文件备份，恢复数据按会话隔离。用户保存或明确放弃后只清理当前会话的恢复项。
- **生成边界**：后台不访问控件；输入包括项目快照、输出路径和声音包快照，输出包括已完成题组、整套文件及取消/错误。SAPI 和外置 helper 支持取消。失败只保留完整产物，旧有效结果不被半成品覆盖。
- **缓存边界**：语音 key 由正文、角色、音色、口音、WPM、引擎相关配置及算法版本派生；题号、重复和停顿不进入语音 key。读取缓存时检查 WAV 合约；编排独立复用语音。
- **搬运边界**：导出新目录，内含工程及显式引用的完整音频；不携带私钥、模型或原始 cache。引用使用相对路径；原工程绝对路径继续可读。新目录不得覆盖已有用户目录，音频缺失必须告知。

验证以编辑撤销、草稿往返、恢复生命周期、取消与缓存回归、真实 GUI 生成和搬移后播放为依据。
